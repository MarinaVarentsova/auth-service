2. BRUTE FORCE / БОТЫ / DDOS НА УРОВНЕ ПРИЛОЖЕНИЯ
==================================================

НЕ запускать нагрузочный тест.

По коду определить защиту от:

— массового login;
— password brute force;
— credential stuffing;
— массовой регистрации;
— массового resend verification;
— массового forgot password;
— массового reset password;
— enumeration email;
— повторного использования token;
— replay;
— 100/1000 одновременных запросов.

Найти:

— rate limiter;
— лимит по IP;
— лимит по email;
— лимит по userId;
— временную блокировку;
— cooldown;
— CAPTCHA, если существует;
— request timeout;
— body size limit;
— maximum field lengths.

Ответить отдельно:

Может ли бот сделать 10 000 login attempts?

Может ли бот вызвать 10 000 verification emails?

Может ли бот вызвать 10 000 password-reset emails?

Может ли бот зарегистрировать тысячи аккаунтов?

Что конкретно остановит его сейчас?

5. CONSENTS
==================================================

Проверить новую реализацию auth_consents.

Регистрация должна:

personal_data=false → 400
platform_rules=false → 400
marketing=false → регистрация разрешена.

При успешной регистрации:
ровно 3 записи.

Проверить:

— user_id;
— email;
— document_type;
— document_version;
— accepted;
— accepted_at;
— revoked_at.

Проверить атомарность:
user + consents.

Проверить, что ошибка записи consent не оставляет пользователя без consent.

Проверить, что marketing действительно НЕ обязателен.

Ничего в БД не менять.
