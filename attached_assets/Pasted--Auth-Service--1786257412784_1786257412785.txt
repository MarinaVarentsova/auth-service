ЗАДАЧА

По результатам аудита в Auth Service существует небезопасный fallback для AUTH_SECRET:

если process.env.AUTH_SECRET отсутствует, код может использовать значение вроде:

"dev-secret"

или другое заранее заданное значение по умолчанию.

В production это недопустимо.

1. Найди ВСЕ места в Auth Service, где используется AUTH_SECRET.

2. Найди все fallback-значения для AUTH_SECRET:
   - "dev-secret"
   - hardcoded secret
   - значение через `||`
   - значение через `??`
   - любое другое значение по умолчанию.

3. Удали возможность работы JWT с fallback-секретом.

Должна остаться только работа с:

process.env.AUTH_SECRET

Никаких запасных/default/dev секретов быть не должно.

4. Если AUTH_SECRET отсутствует или пустой:

НЕ продолжать работу с JWT.

НЕ подставлять другой secret.

НЕ отдавать пользователю технические подробности:
- AUTH_SECRET
- JWT
- env
- stack trace
- название переменной
- внутреннюю ошибку сервера.

Для пользовательского API-ответа использовать безопасное сообщение:

"Сервис временно недоступен. Мы уже работаем над исправлением."

HTTP status: 503 Service Unavailable.

5. При этом в SERVER LOG можно записать техническую причину ошибки, например:

[AUTH] AUTH_SECRET is missing

Но секрет или другие ENV-значения в лог не выводить.

6. Если AUTH_SECRET существует — ВСЁ должно работать абсолютно как сейчас.

То есть изменение не должно повлиять на:
- регистрацию;
- вход;
- проверку текущего пользователя /me;
- access token;
- refresh token;
- logout;
- подтверждение email;
- восстановление пароля;
- сохранение consent;
- существующих пользователей.

7. Не генерировать новый AUTH_SECRET и не менять существующий.

Production AUTH_SECRET уже установлен в Coolify.

8. После изменения выполнить существующие проверки/build/tests.
