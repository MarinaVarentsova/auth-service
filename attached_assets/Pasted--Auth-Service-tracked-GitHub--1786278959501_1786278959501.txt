Работаем ТОЛЬКО в текущем проекте Auth Service.

ЗАДАЧА:
очистить текущую tracked-версию GitHub-репозитория от старых неиспользуемых артефактов, персональных данных и инфраструктурных хвостов.

ВАЖНО:
- НЕ менять production runtime;
- НЕ менять business logic регистрации/авторизации;
- НЕ менять login/register/logout/me/verify/reset;
- НЕ менять JWT;
- НЕ менять Prisma/БД;
- НЕ менять ENV;
- НЕ устанавливать пакеты;
- НЕ делать push;
- НЕ переписывать git-history.

Сначала анализ → затем удаление ТОЛЬКО однозначно неиспользуемых tracked-файлов.

==================================================
1. ПЕРСОНАЛЬНЫЕ ДАННЫЕ В GIT
==================================================

Проверить ВСЕ tracked-файлы текущего репозитория на:

- реальные ФИО;
- реальные email;
- телефоны;
- адреса;
- данные пользователей;
- production logs;
- database dumps;
- CSV/XLSX/JSON/TXT с реальными пользователями;
- скриншоты/вложения с ПД.

Отличать реальные ПД от очевидных test fixtures.

Если найден файл с реальными ПД:
перед удалением подтвердить:

RUNTIME_REFERENCE_COUNT = 0
BUILD_REFERENCE_COUNT = 0
TEST_REFERENCE_COUNT = 0
DEPLOY_REFERENCE_COUNT = 0

Только после этого удалить файл из текущей tracked-версии.

==================================================
2. СТАРЫЙ OPENAI
==================================================

OPENAI_API_KEY из production ENV уже удалён вручную.
В рабочем Auth Service OpenAI использоваться не должен.

Проверить tracked-файлы на:

OPENAI_API_KEY
api.openai.com
openai.com
OpenAI SDK
new OpenAI
openai package
gpt-*
старые OpenAI инструкции/debug snippets/Pasted-файлы.

Каждое совпадение классифицировать:

LIVE_RUNTIME
CURRENT_DOCUMENTATION
OLD_UNUSED_ARTIFACT
COMMENT
TEST_FIXTURE

Удалять ТОЛЬКО OLD_UNUSED_ARTIFACT.

Если LIVE_RUNTIME обнаружен — НЕ менять код, а остановиться и показать точное место.

НЕ менять текущую конфигурацию Coolify.
