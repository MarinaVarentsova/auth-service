==================================================
3. УБРАТЬ TOKEN ИЗ HTTP RESPONSE
==================================================

После успешной регистрации HTTP response
НЕ должен содержать:

verification_token
rawToken
token
verificationUrl

или другое поле,
через которое browser получает secret verification token.

Сохранить все остальные существующие поля успешного response,
которые реально нужны frontend.

Например, если сейчас response содержит:

{
  success,
  user_id,
  project_id,
  status,
  verification_token
}

то должно стать:

{
  success,
  user_id,
  project_id,
  status
}

Не менять значения остальных полей.


==================================================
4. ПРОВЕРИТЬ FRONTEND DEPENDENCY
==================================================

Проверить весь текущий frontend,
используется ли response.verification_token
после регистрации.

Если НЕ используется:
ничего во frontend не менять.

Если используется:
не возвращать raw token обратно ради совместимости.

Изменить только frontend-поведение так,
чтобы registration success flow продолжал работать
без доступа к verification token.

Пользователь должен после регистрации
по-прежнему видеть текущий success UX
и получать verification email.
