Работаем ТОЛЬКО в artifacts/api-server.

Исправляем ОДНУ security-проблему:

в production отсутствует явный безопасный набор HTTP security headers.

Нужно добавить минимальный security baseline
для api-server,
НЕ меняя его API-логику.

НЕ проводить общий аудит.
НЕ менять:
- Палату;
- Auth Service;
- AI Gateway;
- БД;
- Prisma;
- CORS;
- notify business logic;
- UniSender;
- ENV;
- Docker/Coolify.

НЕ делать commit/push/deploy.


==================================================
1. ПРОВЕРИТЬ ТЕКУЩИЕ HEADERS
==================================================

Проверить:

artifacts/api-server/src/app.ts

и связанные middleware.

Найти:

helmet
Content-Security-Policy
X-Content-Type-Options
X-Frame-Options
Referrer-Policy
Permissions-Policy
Strict-Transport-Security
Cross-Origin-*
X-Powered-By

Если часть уже есть — не дублировать.


==================================================
2. ДОБАВИТЬ SAFE BASELINE
==================================================

Для production добавить:

X-Content-Type-Options: nosniff

X-Frame-Options: DENY

Referrer-Policy:
strict-origin-when-cross-origin

Permissions-Policy:
camera=(), microphone=(), geolocation=()

Cross-Origin-Opener-Policy:
same-origin

Cross-Origin-Resource-Policy:
same-origin
ТОЛЬКО если это не ломает существующие API responses.


==================================================
3. X-POWERED-BY
==================================================

Отключить:

X-Powered-By

После изменения:

X_POWERED_BY_EXPOSED = NO


==================================================
4. CSP
==================================================

api-server — API backend.

Не добавлять сложный CSP,
если он не нужен JSON API.

Если Helmet используется,
CSP можно отключить,
если он не даёт реальной пользы для этого backend.

CSP_ENABLED = YES/NO


==================================================
5. HSTS
==================================================

Если api-server реально доступен только через HTTPS reverse proxy,
можно включить HSTS.

Но:

- без preload;
- без includeSubDomains без необходимости.

Если не уверен —
не включать.

HSTS_ENABLED = YES/NO


==================================================
6. CORS НЕ МЕНЯТЬ
==================================================

Текущий CORS уже исправлен ранее:

production:
https://platformaekspertov.ru

dev:
localhost/127.0.0.1 только вне production

Старый sslip.io удалён.

ЭТУ ЛОГИКУ НЕ ТРОГАТЬ.


==================================================
7. НЕ ЛОМАТЬ API
==================================================

После изменений должны работать:

- /api/notify;
- existing API endpoints;
- Authorization;
- OPTIONS/preflight;
- CORS;
- server-to-server calls.

Не менять:
status codes,
JSON responses,
payloads.
